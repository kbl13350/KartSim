# KartSim 可开发工程

这里是依据本地镜像的 KartSim v39.11 前端发行文件重建的开发工程。应用已按资源、驾驶、车辆、世界、界面、计时赛和联机等边界拆为 ES 模块，并能使用同目录外的 `mirror/` 资源运行。它不是游戏作者的原始仓库：发行文件没有提供原始 source map，原文件名、注释和大部分变量名无法可靠还原。

## 运行

需要 Node.js 24、npm、Python 3，以及仓库根目录已通过 Git LFS 拉取的 `mirror/p3553`。新克隆的仓库需先按[根目录说明](../README.md#启动)运行 `git lfs pull`，再在本目录执行：

```sh
npm ci
npm run dev
```

开发地址为 <http://127.0.0.1:8780/>。首次进入时选择“使用在线资源”；在这个地址下，它会读取本机 `../mirror/p3553`，按需缓存容器。开发服务器只监听本机。

比赛默认关闭游戏侧垂直同步，可在“设置 → 显示/音量”中切换“垂直同步（比赛）”。关闭时，比赛的输入和模拟在两次屏幕刷新之间由消息任务约每毫秒推进一次，渲染只在 `requestAnimationFrame` 中提交，每次刷新先推进到当前毫秒再绘制一帧；开启时推进和绘制都只在刷新时进行。菜单、暂停、结算及后台页面仍使用浏览器帧调度。FPS 表示实际绘制的帧率，性能足够时等于屏幕刷新率。主 3D 画布最多渲染 1920×1080 像素，小视口保持原分辨率，独立界面画布仍按设备分辨率绘制。地图和天空的几何数据会在加载阶段预热，以减轻开局首帧上传负担。

如需本地多人服务和档案持久化，请在仓库根目录运行 `./run-full-local.sh`。它启动前端 `127.0.0.1:8780`、数据服务 `127.0.0.1:8787` 和游戏服务（`127.0.0.1:8788` 起）。前端配置的后端地址即数据服务：账号、档案、历史、游戏服务器列表与入场票据都走它；进入多人大厅时先选择游戏服务器（只有一个可用时自动进入），每次连接都向数据服务申请一次性票据，再用 WebSocket 连接该游戏服务器的 `/multiplayer/ws`，会话 token 不会发给游戏服务器。不再加载镜像里指向远程站点的 `multiplayer-config.js`。游戏必须登录账号后才能进入（没有游客或离线模式），所以单独启动前端时会停在登录界面并提示“无法连接数据服务”，启动数据服务后点“重试”即可；进入多人大厅还需要至少一个游戏服务。可通过 `VITE_MULTIPLAYER_BACKEND_ORIGIN` 改数据服务地址，通过 `VITE_MULTIPLAYER_TRANSPORT=webrtc` 切回原协议；跨域地址需由服务端允许。

账号与经济（约定见 [`server-go/ECONOMY.md`](../server-go/ECONOMY.md) 第 7、8 节，实现在 `src/account/`）：资源加载后、首页出现前先显示登录/注册对话框（开放注册：账号名、昵称、密码与确认密码；仅邀请模式显示邀请码）。登录 token 存在 `localStorage`，记住 30 天，并与多人游戏共用（`kartsim.multiplayer.session:<数据服务地址>`），进入多人大厅时不再弹出账号或游客昵称对话框。新账号先完成原版新车手对话框（只能选皮蛋/黑妞与 `newRiderItem@cn` 的 6/4/5/7 号颜色，昵称预填账号昵称），领取新手礼包：系统练习车、所选角色、喷漆与染色。车库（Ready 选道具、全屏车库、小屋“我的物品”、多人房间选车）只列出账号库存中未过期的物品，限时物品在卡片上显示“剩余 N 天”；比赛、影子、其他玩家、RP 借车、故事借车和大厅场景仍使用完整资源目录。已装备物品过期或不再拥有时自动换回：赛车→练习车，角色→新手角色，喷漆/染色→新手颜色，其他槽位卸下。任务栏“商店”和首页顶栏点券、K 币旁的“+”打开商店（`src/shop/`）。计时赛完成后向数据服务结算，结果面板原版 RP/Lucci 位显示获得的经验和金币；多人比赛结果每行显示该车手的“+经验 +金币”，赛后自动刷新账号，升级时弹出提示。

车库资料（收藏、锁定、小屋设置、车库改装与装备）登录后与账号绑定，读写数据服务的 `/api/account/profile`，以服务端为准；浏览器 `localStorage` 只保留该账号的缓存。某个账号第一次登录且服务端还没有档案时，只从本机原有的匿名档案迁移收藏、锁定、小屋设置、号牌文字和车库改装，装备一律按库存修正。计时赛成绩摘要同步到 `/api/records/{ownerId}/ghost-summary-index`；影子回放帧仍保存在浏览器 IndexedDB，因此从服务端导入的摘要不会错误地显示为可播放回放。浏览器密钥存于本地 `localStorage`，清除站点数据会失去访问该服务端档案的密钥，请在迁移浏览器前备份站点数据。

启动后的首页是大厅：背景是玩家自己小屋设置的地图（档案 `myRoom.environmentId`，原版 `myRoom.rho`；未设置时用默认地图），当前人物与已装备赛车并排站立：后排车位是一条直线的地图，站在第 4、第 5 个停车位（`parking04`、`parking05`）稍前方；第 4、5 位拐到角上或侧面、是抬高陈列架（VIP 小屋）或缺失的特殊小屋，站在前厅中心，即原版 8 个车手站位 `rider00`–`rider07` 的中心。镜头都按小屋原本的方向拍（`src/ui/lobby-home-view.ts`，站位与机位见 `my-room-scene.ts` 的 `myRoomShowcaseCenter` 和 `myRoomShowcasePose`）。在小屋里换了地图，回到首页即生效。顶部是车手栏，图标都用原版素材：等级图标按 `etc_/level/leveltable@cn.xml` 取该等级的手套（`etc_/level/<手套>.png`），点券、金币、K 币用 `dialog2_/personalShop/img_cash`、`img_lucci`、`img_koin`，充值按钮是原版顶栏的 `gui_/window/menu/btn_chargeKoin_`；车手名、等级手套（按账号摘要的 `progress.glove` 读取 `etc_/level/<手套>.png`）、经验条与三种余额随账号实时刷新（购买、比赛、升级后）；点击头像或名字打开账号面板，可查看账号名、等级经验、余额、战绩与注册时间，修改昵称或退出登录（多人房间或比赛中不能退出）。左侧“快速进入”默认是竞速个人赛、无限加速个人赛、计时挑战赛和赛道对决（尚未开放），齿轮按钮可改选最多 5 项并保存在浏览器本地；右侧是宣传轮播和两块“COMING SOON”展板。小屋场景容器约 73 MB，首次进入时先显示静态背景，加载完成后淡入。

多人游戏的房间列表分竞速赛、道具赛（尚未开放）和 ETC 三个标签，左侧是分类（竞速个人赛、竞速组队赛、竞速自订、无限加速赛；ETC 下是各娱乐模式），竞速自订可按个人赛、团体赛、无限个人、无限团体筛选。房间名称前是原版选赛道窗口的主题图标，背景是大厅场景的模糊画面。滚轮翻页；“快速开始”（F5）加入当前分类第一个公开的空闲房间，没有时打开创建房间。标签背景与分类旗帜是 `../mirror/ui/multiplayer/` 下的 `tab-speed.webp`、`tab-item.webp`、`tab-etc.webp` 与 `category-flag.png`，替换同名文件即可换图。

进入 Ready 后可从底部任务栏打开“小屋”，在首页上方的游戏区域显示场景，并保留底部任务栏。场景读取原版 `myRoom.rho` 的环境清单，加载对应的 `track.1s` 与 `skydome.1s`，在原版车手与停车位站位显示当前人物和已装备赛车；人物使用普通角色模型，并分别播放原版直立待机与步行动作。WASD 或方向键移动人物、滚轮缩放视角，并可切换主题。小屋名称与留言是当前 Web 版的本地设置。小屋内的“我的物品”参照原版 `dialog.rho` 的仓库分类、四列布局、搜索和卡片状态；只列出账号库存中未过期的物品（限时物品显示剩余时间），从商店购买后即可在这里装备。已有档案装备槽但尚无比赛场景外观或效果的类别会在仓库中标明。星标、赛车锁定、小屋设置及装备变化保存在同一份本地档案，并按上述方式同步到数据服务。原版的访客、聊天、抽奖和消耗品操作尚未接入。逆向依据与实现边界见 [小屋与仓库资源分析](MY_ROOM_REVERSE_ENGINEERING.md)。

一键检查并打包：

```sh
npm run verify
./run-built.sh
```

打包版默认地址为 <http://127.0.0.1:8781/>。`dist/` 中的资源目录是指向 `../mirror` 的相对符号链接，因此应连同本工程和镜像一起使用；它并不是独立的 3.49 GiB 离线安装包。可以给 `run-built.sh` 传入端口号。

启动后，`src/main.ts` 注册 Service Worker，安装赛道世界方法，再加载 `src/generated/app.js`。`Sw.load` 与 `Sw` 的资源业务方法由生成器接到新代码。兼容模块维持尚未迁移的菜单、渲染及业务方法。生成器把已验证的驾驶、资源、车辆表现、界面交互、应用控制、影子记录、计时赛和联机实现接入运行路径。新逻辑优先在对应 TypeScript 目录实现，再通过生成器的 override 接入；请勿直接修改 `src/generated/`。生成细节见 `tools/README.md`。

## 继续开发的方法

1. 从 `src/game/api.ts` 的可读导出名和 `recovered/analysis/architecture.md` 找到系统入口。
2. 对照 `recovered/formatted/index.js` 与 `recovered/data-full/` 的配置，先确定当前行为、数据格式和调用点。`recovered/` 是供追溯的发行版还原稿，不是新工程的编辑入口。
3. 在 `src/` 写带类型的新模块，并用真实镜像数据或原实现的差分结果验证。
4. 需要让游戏实际使用新模块时，在 `tools/generate-modules.mjs` 中加入稳定的声明替换与导入，再运行 `npm run generate`、`npm test`、`npm run typecheck`、`npm run build`。浏览器中至少复测菜单、车库及进入计时赛。

`npm run generate` 以固定哈希的发行版文件为输入；如果下载版本改变，它会拒绝继续，避免悄悄生成不匹配的应用。资源清单和容器同样按版本与修订号校验。Service Worker 路由 `.rho`、`.rho5`、`aaa.pk` 和音频 WASM；大文件按需从本机静态服务流式读取，不会在 SW 缓存里复制整份镜像。详细缓存行为见根目录 `README.md`。

模块依赖、各生成模块职责及迁移检查点见 `ARCHITECTURE.md`。

## 已验证的范围与剩余工作

目前已在浏览器里跑通：本地资源加载、创建本地车手、计时赛菜单、车库懒加载及车型/部件列表、进入真实赛道并显示赛车和计时界面；连续加速输入使车速变化，暂停后可以返回 Ready。最新构建走过这条路径时，浏览器控制台没有警告或错误。接入的新解码器建立的 137,609 个虚拟条目与原资源库的路径/元数据逐项一致；输入与影子记录替换有发行实现差分测试。资源清单、档案索引和 Rho/Rho5 解码测试使用真实 p3553 数据，车辆参数表与查询结果也已逐项核对。

影子记录的帧编解码与存储还经过真实浏览器 IndexedDB 写入、读取、列举和删除验证；可在开发服务器打开 `/tests/browser/ghost-store.html` 重测。KSV 外层格式也已手写，可用 `/tests/browser/ksv-codec.html` 检查浏览器读写闭环；底层 zlib 使用 `pako@2.1.0`，字节输出已与发行版逐项比对。

`src/generated/` 当前仍有约 1.0 MB 的场景格式、渲染、界面、车辆和车库兼容代码保留发行版压缩名称。完整手写重构尚未完成；每个已替换范围都由 `src/generated/manifest.json` 和相应的差分测试标明。暂停菜单资源、画布交互和赛前车辆预览已迁到 `src/timeattack/`，并在真实浏览器中验证进入赛道和 Esc 暂停。原网页只交付浏览器客户端，仓库内 `server/` 是依照可观察协议新写的 Java 实现，`server-go/` 是它的 Go 重写（一个数据服务加多个游戏服务节点）。联机协议边界见 `src/multiplayer/README.md`。
